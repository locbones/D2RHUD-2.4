# Native inventory image binding (D2R 2.4)

Inspected the user-supplied `D2R.exe` at `C:\Users\djsch\Desktop\Pandemonium-Windows\Pandemonium\D2R\D2R.exe`, SHA-256 `e4e13570e60c0a65cb0469d6659be8a6008f9433ac50db1c4f94501d7d9016f8`. Addresses below are RVAs; the preferred image base is `0x140000000`. These are static observations from PE bytes decoded with pefile/Capstone, not claims of in-game execution. REA's GNU objdump route is unavailable on this Windows host, and full Ghidra auto-analysis is impractical for focused iteration on this executable.

- ImageWidget factory `0x578fd0` allocates `0x120` bytes and installs vtable `0x157bfa8`. OnLoad is `0x5790f0`, draw `0x578d10`, message handling `0x578d50`.
- OnLoad `0x5790f0` passes its own `+0x110` field, filename at `+0xe8`, and `false` to `0x573670`. It assigns `+0x88 = this+0x110`, then calls `0x578c30` to set natural rect dimensions. The `+0xe8` field is an owned native string and must not be overwritten with HUD-owned text.
- Native resource loader `0x573670` first calls resource release `0x573850`, then prefixes the filename with `data/hd/global/ui/` or `data/global/ui/` according to the game's graphics mode. HD loading uses `0x4fbc20`, legacy loading `0xba4df0`. The replacement uses this routine and leaves filename/string ownership intact.
- Destructor `0x176090` explicitly calls `0x573850(this+0x110)` before freeing the native filename and base widget. Thus the game owns replacement sprite lifetime too.
- Size getter `0x573930(resource, uint64_t* dimensions, int frame)` writes packed width/height. Image draw `0x578de0` passes resource `+0x88`, frame `+0x90`, and the native parent scale multiplied by `+0x80` to the game's draw routine `0x573440`.
- `0x576f00` resolves a widget's position from rect x/y `+0x70/+0x74`, its parent geometry/anchor and parent scales. The bridge preserves initial x/y as the icon box origin and centers a native scaled sprite inside explicit box dimensions.
- Normal inventory path builder `0x87ee0` builds `items/{category}/{asset}`. Category getter `0x42d230` returns `weapon`, `armor`, or `misc` from actual compiled item-table ranges. Base asset paths come from `hd/items/items.json`; unique/set paths come from their corresponding JSON mappings.
- `0x880bb..0x88110` appends a decimal graphics variant for non-named items with variant count >0. The variant is `min(count, max(1, itemData.byte[0x5e]+1))`; a named override suppresses this suffix.
- Named asset tier resolution `0x42d550` compares the requested base code to the named item's original compiled code (`+0x28`) first, choosing JSON `normal`. Otherwise it compares against that original base's compiled uber/ultra codes (`+0x88/+0x8c`), selecting `uber`/`ultra`. Selection is relative to the named item's original base, including named exceptional/elite items.
- Native name canonicalizer `0x42a890` trims trailing spaces and `)`, lowercases ASCII, removes apostrophes, and substitutes other non-alphanumeric characters with underscores. It inserts an underscore after an alphanumeric character when the next character is uppercase or when a nondigit is followed by a digit. Callsites include `0x42b26b`, `0x42b6cb`, `0x42c662`, `0x42c931`, and `0x42f0b1`; the latter copies at most 63 bytes into 64-byte name records. Thus hyphens in names such as `Trang-Oul's Guise` become underscores (`trang_ouls_guise`).

The bridge guards the exact native loader, size getter and ImageWidget OnLoad code with FNV-1a fingerprints over their first 32 bytes. It accepts only native ImageWidgets with the expected vtable slots and self-owned resource pointer. It does not deserialize a unit, insert an inventory object, decode/upload a texture, or submit HUD/ImGui vertices.

`tests/run-marketplace-native-images.cmd` verifies the resource path and ownership contract using injected native routine fixtures, aspect-fit centering, changed-image caching, game-side resource invalidation, clearing, invalid types/paths, and preservation of `+0x88`. Actual game sprite rendering still requires an in-game check.
